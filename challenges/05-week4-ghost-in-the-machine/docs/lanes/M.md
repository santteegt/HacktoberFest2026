## Where the code differs from the brief (the diagram follows the code)
1. The chain in `ghosts/haunt.py` is pick → summon → wounds → classify → face → story → render → og → gallery → deploy. There is a `face` step (Wayback screenshots, never fatal) the brief left out, and `verify` and `fix` are not separate steps: they run inside `story` (`story.tell`). The diagram shows them in an "inside story" inset.
2. Gemma is called in four places, all inside `story`: one call per chapter, one repair call per failing sentence, one title-and-tagline call, and the fix name mapping (up to two tries). The brief did not list the title call.
3. The pipeline does not use the OpenAI-compatible endpoint: `ghosts/llm.py` calls Ollama's native `/api/chat` on 127.0.0.1:11434 with `gemma4:12b-it-qat`, 8k context. Only Hermes uses `http://localhost:11434/v1`, with the alias `ghosts-gemma4-12b` (same weights, 64k context).
4. "Is the code still there" (`eth_getCode`) and the balance go to PublicNode (`RPC_URL`, ethereum-rpc.publicnode.com), not dRPC. dRPC (`ARCHIVE_RPC_URL`) serves old full blocks: the random picker and birth-block timestamps.
5. Discord delivery is `hermes -p ghosts send --to discord` called by `haunt.sh`, with a line built in code; the crons themselves are `deliver: local`.
6. `og` always runs but never stops the chain (like `face`); `deploy` runs only with `--deploy` (both crons pass it).
